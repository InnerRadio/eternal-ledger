======================================================================
1. PURPOSE
======================================================================

This contract defines the persistence evolution required by the locked
Server-Issued Journey Reference Authority v1.

It defines:

    model field semantics
    live SQLite column semantics
    uniqueness requirement
    index requirement
    migration method
    preconditions
    postconditions
    rollback boundary
    verification requirements

It does NOT perform the migration.


======================================================================
2. REQUIRED FIELD
======================================================================

AttributionContext requires:

    journey_reference_hash

Semantic type:

    String

Canonical contents:

    lowercase hexadecimal SHA-256 digest

Expected length:

    64 characters

It represents:

    SHA-256(raw server-issued journey reference)


======================================================================
3. RAW REFERENCE MUST NOT BE STORED
======================================================================

The database must store only:

    journey_reference_hash

The database must NOT store:

    raw journey reference
    plaintext bearer secret
    reversible encrypted journey reference

The browser may carry the raw opaque reference.

The database stores the digest only.


======================================================================
4. NULLABILITY
======================================================================

The target steady-state model semantics are:

    journey_reference_hash
        non-null
        for journey-enabled Attribution Context records

Because the attribution_contexts table is currently empty, the schema
may be evolved directly to a NOT NULL column without requiring legacy
row backfill.

This assumption is valid ONLY while row count remains zero.

If rows appear before implementation, STOP and redesign the migration.


======================================================================
5. UNIQUENESS
======================================================================

journey_reference_hash must be unique.

Reason:

The same active journey reference must resolve to at most one canonical
Attribution Context.

Database uniqueness is required to protect:

    accidental duplicates
    concurrent creation races
    application-level logic failure

Random collision probability alone is not sufficient integrity
authority.


======================================================================
6. INDEXING
======================================================================

journey_reference_hash must be indexed.

Reason:

The canonical continuation lookup is:

    presented raw reference
        ↓
    SHA-256
        ↓
    lookup Attribution Context by journey_reference_hash

This is a direct lookup path and requires an index.


======================================================================
7. MODEL TARGET
======================================================================

Expected SQLAlchemy model semantics:

    journey_reference_hash = Column(
        String,
        nullable=False,
        unique=True,
        index=True,
    )

The exact formatting of models.py is not authoritative.

The semantics are.


======================================================================
8. SQLITE TARGET
======================================================================

The live attribution_contexts table must contain:

    journey_reference_hash VARCHAR NOT NULL

and database-enforced uniqueness.

A unique index or SQLite UNIQUE constraint may satisfy the uniqueness
requirement.

The implementation must verify the actual live SQLite result rather
than assume SQLAlchemy metadata changed the existing table.


======================================================================
9. CREATE_ALL IS NOT THE MIGRATION
======================================================================

SQLAlchemy Base.metadata.create_all() does not alter an existing table
to add missing columns.

Therefore:

    editing models.py
    +
    running create_all()

is NOT sufficient schema evolution.

The live SQLite schema must be changed explicitly.


======================================================================
10. CURRENT EMPTY-TABLE ADVANTAGE
======================================================================

The current attribution_contexts table contains zero rows.

This provides a clean schema-evolution window.

There is no legacy Attribution Context data requiring:

    backfill
    default fake hashes
    temporary NULL values
    per-row migration

The migration must preserve this zero-row state.


======================================================================
11. NO FAKE BACKFILL
======================================================================

The implementation MUST NOT invent placeholder values such as:

    ""
    "unknown"
    "legacy"
    sequential hashes
    shared default hash

No fake journey identity may be created merely to satisfy NOT NULL.


======================================================================
12. MIGRATION STRATEGY
======================================================================

Because SQLite ALTER TABLE support is limited and the target includes:

    new NOT NULL field
    uniqueness
    indexing

the implementation should use an explicit transactional table-rebuild
migration for attribution_contexts.

Conceptual procedure:

    BEGIN IMMEDIATE

    verify attribution_contexts row count == 0

    verify expected current schema

    create attribution_contexts_new
        with full target schema

    create required indexes / uniqueness

    verify new schema

    drop old attribution_contexts

    rename attribution_contexts_new
        to attribution_contexts

    verify final schema

    COMMIT

If any required step fails:

    ROLLBACK


======================================================================
13. NO DESTRUCTIVE RECREATION WITHOUT GUARDS
======================================================================

The table-rebuild migration is permitted only because:

    current row count == 0
    expected source schema is known
    target schema is known
    transaction guards the operation

The implementation MUST NOT blindly:

    DROP TABLE attribution_contexts

and recreate it without precondition checks.


======================================================================
14. TRANSACTIONAL AUTHORITY
======================================================================

The migration must occur inside an explicit SQLite transaction.

Preferred acquisition:

    BEGIN IMMEDIATE

Reason:

Schema evolution must not race with another writer.

The migration should either:

    complete fully

or:

    leave the original schema intact through rollback.


======================================================================
15. PRECONDITIONS
======================================================================

Before migration, verify:

1. repository protected checkpoint

2. models.py exact expected pre-migration hash

3. attribution_contexts exists

4. attribution_contexts row count == 0

5. journey_reference_hash absent

6. expected existing 18-column contract present

7. no unexpected indexes

8. database backup created

9. tracked Git boundary known

If any precondition fails:

    STOP


======================================================================
16. DATABASE BACKUP
======================================================================

Before live schema evolution:

    create a timestamped byte-for-byte backup of eternal_ledger.db

Verify:

    SHA256(original) == SHA256(backup)

The backup must occur before the first database write.


======================================================================
17. MODEL / DATABASE COORDINATION
======================================================================

models.py and the live database schema must land together in one
verified implementation milestone.

The system must not be left intentionally in a state where:

    model expects journey_reference_hash
    but live table lacks it

or:

    live table contains journey_reference_hash
    but committed model lacks it

21. UNIQUE NULL SEMANTICS DO NOT MATTER IN TARGET STATE
======================================================================

The target field is NOT NULL.

Therefore SQLite's behavior allowing multiple NULL values in UNIQUE
indexes is not relevant to the steady-state authority.

No journey-enabled Attribution Context should exist without a digest.


======================================================================
22. DIGEST LENGTH VALIDATION
======================================================================

Database VARCHAR does not itself enforce a 64-character digest length
in SQLite.

Therefore application creation authority must later validate:

    exactly 64 lowercase hexadecimal characters

before persistence.

This schema contract does not add a CHECK constraint in v1.

A future stricter integrity migration may do so.


======================================================================
23. DIGEST CONTENT VALIDATION
======================================================================

The live schema guarantees:

    non-null
    uniqueness
    lookup indexing

It does not alone prove:

    lowercase
    hexadecimal
    SHA-256 origin

Those are Creation / Journey Reference Authority responsibilities.


======================================================================
24. ROTATION SEMANTICS
======================================================================

Reference rotation later updates:

    journey_reference_hash

on the SAME Attribution Context.

Uniqueness continues to apply to the replacement digest.

Rotation must not create a second Attribution Context merely to change
the reference.


======================================================================
25. OLD HASH AFTER ROTATION
======================================================================

The v1 schema stores only the currently active journey_reference_hash.

It does NOT preserve previous active hashes in the Attribution Context
row.

Therefore after successful rotation:

    old hash is no longer current authority

Historical rotation auditing may later require a separate audit or
provenance record.

That is outside this schema evolution.

29. ROLLBACK BOUNDARY
======================================================================

    any failure → ROLLBACK

verified pre-migration database backup and restore the pre-migration
models.py backup.

Rollback must be explicit and byte-verified.
